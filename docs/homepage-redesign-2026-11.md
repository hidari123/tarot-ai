# Mystic Tarot 首页优化方案（竞品调研版）

> 调研日期：2026-11-18 · 状态：**方案稿，未改任何代码**
> 调研方法：先实拍当前首页（1280×720 笔记本视口 + 全页），再横向拆解 15+ 个占卜/占星产品的首页结构。

---

## 一、结论

当前首页的视觉完成度已经相当高——人物、水晶球、星空、魔法阵、字体的氛围感是同类产品里少见的，**它不缺少美，缺的是"用户第一眼知道该干什么"**。

实拍 1280×720 的结果暴露了核心问题：**首屏里没有任何一个可操作元素**。标题 MYSTIC TAROT、副标题「倾听星辰的低语 / 窥探命运的轨迹」之后，是一张占掉首屏七成高度的人物大图，直到接近折叠线才露出第一张入口卡片。输入框、「开始占卜」按钮、占卜师选择全部在**第 1.5 屏以下**，整页高度 2840px（约四屏）。

竞品调研指向同一个结论：这一代占卜产品的首页竞争点已经从"好看"转移到"**首屏能否在几秒内回答『我今天能得到什么』**"。Co-Star 被反复称为"设计标杆"，理由不是它的星盘有多精致，而是它的 **snapshot-first**——打开就是今天的具体内容，而不是一句品牌口号。The Pattern 的做法是把占星术语换成平实语言，一次只问一个问题；CHANI 把它总结为「预测 → 应对」，看完解读立刻给一个可执行的下一��；Labyrinthos 干脆把首页让给"学习"——免费、无需登录、牌义库 + 课程 + 日志。

**但这些产品没有一个能直接照抄。** Co-Star 的快照优先建立在"用户早已录入出生数据"的前提上，我们没有；CHANI 的每日仪式建立在原生 App 的推送与订阅体系上，Web 单页承载不了。真正可迁移的是它们的**结构原则**：把主 CTA 放进首屏、把次要入口降级、用一个零门槛动作替代"必须先做一堆选择"、以及在首屏给出可信度信号。

所以本方案的核心判断是：**首页不用重做，需要的是重排。** 现有的氛围资产（人物 + 水晶球 + 星云）应该保留并下移，把输入框和 CTA 提到副标题正下方，让首屏变成「品牌名 → 一句功能说明 → 输入框 → 开始占卜 → 零门槛次级入口」的顺序。改动集中在 `page.tsx` 的渲染顺序与三个内联组件的尺寸变量，不需要重写视觉系统。

## 二、竞品首页的三种范式

调研中有大量"2026 最佳塔罗 App"类榜单，但它们彼此矛盾且普遍挂返佣链接——Statpit 把 Labyrinthos 列第一，Gaugius 把 Golden Thread 列第一，两篇文章结构几乎一样、结论互斥。这类内容只能用来交叉验证"哪些产品被反复提及"，不能当设计依据。真正可采信的是第一方页面与官方文档，从它们能提炼出三种稳定范式。

**第一种是快照优先（snapshot-first）**，代表是 Co-Star。首页打开即给当天的具体内容：一段简短但有锋芒的当日解读，加一个一点就开的星盘。它用极简直白取代神秘符号，主动把"专业感"让位给"今天跟我有什么关系"。配套的导航也是四五个固定标签（今日、这一周、成长、我、行运），把复杂度压在固定结构里。

**第二种是渐进式提问（one question at a time）**，代表是 The Pattern 和我们自己的 HITL 流程。它的做法是用平实语言替代术语，把时间讲成"性格模式"而不是"行运相位"。更值得注意的是它从不在首屏抛出选项列表，而是先给内容、给兴趣点，等用户表达出方向后再收窄。The Pattern 的评测里被反复提到的优点是"calm"——冷静来自不让用户做决定。

**第三种是仪式加行动（ritual → action）**，代表是 CHANI。它的产品逻辑被归纳为「预测 → 应对」：传统占星告诉你未来可能怎样，然后把你导向人工咨询去缓解焦虑；CHANI 把这一步彻底产品化——冥想、肯定语、journal 练习都做成了可以直接执行的动作，官方 App tour 里 Home / Grow / Me / Transits / Audio 五个标签，本质是把"我能做什么"和"我是什么"分开承载。商业上这个转向是有效的：CHANI 近 30 天收入 83.25 万美元，同比增 15.17%，稳居全美最赚钱占星应用第一梯队。

其他产品补充了不同的一角。Great-Psychic 的转化设计值得单独一提：「你的前两次每日解读免费，**无需注册**」，主 CTA 直接是 "Get My FREE Reading"——先用免费体验换信任，再谈账号。Labyrinthos 把首页做成学习中心，免费牌义库 + 测验式记忆训练 + Journal，评语是"结构化学习的天花板"。Q-塔罗（中文）用首页「命运之轮」转盘做零门槛的每日轻量入口，配合"每张牌都有自己的性格"的人格化解读。Orabit 走的是诚实路线：明确写"我们不预测，只做反思工具"。

把这些拆开看，跨产品反复出现的设计要求只有五条：宽容快速的引导、首屏几秒内能回答"今天对我意味着什么"、**渐进式披露**而非一次性抛选项、免费可体验而不强制登录、以及移动优先。评测里被点名的反面模式也很一致——"五种内容类型、三条横幅、开屏付费墙"是这一类产品的典型失败。

## 三、当前首页的五处具体问题

以下每一条都基于实拍截图（1280×720 视口 + 2840px 全页），不是推测。

**第一，首屏没有可操作元素。** 标题与副标题之上没有价值说明，副标题之下就是人物大图。这张图本身质量很高，但它占掉了首屏最贵的空间，而用户此刻只有一个疑问："这东西怎么用？"

**第二，价值主张是文学口号，不是功能说明。** 「倾听星辰的低语 / 窥探命运的轨迹」在氛围上是加分的，但它没有回答任何功能性问题。用户在决定要不要投入注意力时需要的是"写下你的问题 → 占卜师会澄清 → 亲手选牌 → 得到结合牌义与典籍的解读"这样一条链路。现有文案在首页最显眼的位置，用最漂亮的字体，说了一句最不实用的话。

**第三，决策点太多且顺序反了。** 主 CTA 之前依次是：5 个占卜师头像、2 种占卜模式、3 张入口卡片。代码上占卜师其实**不是必选项**（`startDivination` 传的是 `persona?.id`，未选也能开始），但视觉上它排在最前，5 个头像一排开，用户会默认"我得先挑一个才能用"。竞品的共同做法恰好相反：先给内容或先接住问题，把选择收进流程内部——我们的承约、呼召、选牌本来就在做这件事，首页却把它全摊开了。

**第四，次要入口占据了黄金位置。** 三张入口卡（今日之牌 / 运势专区 / 问神谕）渲染在输入框**上方**，视觉权重与主任务相同，还额外撑高了页面。竞品普遍把这类入口做成顶栏导航或底部 tab（CHANI 四 tab、占星类应用多为 bottom-navigation），而不是和主 CTA 平级。

**第五，技术栈标签外露给普通用户。** 页尾那行「MYSTIC TAROT · MULTI-AGENT × HYBRID RAG (BM25+VECTOR) × HITL × REFLEXION × SSE」是给面试官看的，对占卜用户是纯噪音，且占据了首屏预算。真正该出现在这里的是**信任信号**——已有多少条解读、引用了多少条典籍、牌义库覆盖多少张牌。这类数字在塔罗类产品里是标准的信任锚点（Labyrinthos 的 50,000+ 下载与 4.7 星、Great-Psychic 的"首次免费"都是同类作用），我们目前一个都没有。

另有一处视觉噪音：首屏左下有一个圆形"N"徽章，且在多个位置重复出现，压在「今日之牌」卡片上。它不属于本任务范围（工作区里还有一批未提交的 nebula 相关改动），但在当前状态下像是调试残留，建议在合并那批改动前一并处理。

## 四、优化方案

按"改动成本 ÷ 收益"分三层。**第一层不动任何视觉资产**，只调渲染顺序和尺寸变量，预期收益已经能覆盖大部分差距。

### P0 · 把首屏让给主任务（纯布局重排）

1. **副标题改为功能说明句**，保留原文学句作为其下一行小字或悬浮时的装饰。示例结构：`写下你的困惑，占卜师会与你对话澄清、亲手选牌、给出结合牌义与典籍的解读` / 副行保留原句。文学性没丢，但信息落到了功能上。
2. **输入框 + 「开始占卜」上移到副标题正下方**，人物大图整体下移或缩放到首屏下半部。
3. **三张入口卡下移到输入框之后**，并降级为一行紧凑卡片（保留图标 + 标题，去掉描述行），或改为顶部横向导航。这样它们不再和主 CTA 争视觉权重。
4. **占卜师选择改为输入框下方的一行**，默认展示为"月影占卜师"这类默认人设 + 一个「换一位」展开控件；模式切换（快速一问 / 深度解读）并入同一行。选人从"必须先做"变成"可选的仪式感参数"。
5. **页尾技术栈标签移出首页**，或替换为信任信号数字。

预期结果：首屏变成「品牌名 → 功能说明 → 输入框 → 开始占卜 → 零门槛次级入口」，用户落地即知如何开始。

### P1 · 补零门槛入口与信任信号

6. **加一个"不提问也能体验"的次级按钮**：在「开始占卜」下方放一行「或 · 抽一张今日之牌」，直接跳 `/daily`。这条路径把"必须先写出一个像样的问题"这个心理门槛拆掉，是 Great-Psychic 与 Q-塔罗都在用的钩子。
7. **首屏加一行轻量信任信号**：例如"已解读 12,847 次 · 引用典籍 2,300 条 · 78 张牌义库"。没有真实数据之前不要编——可以先用**可核实的技术事实**替代，例如"每张解读都附典籍出处"（这一点项目确实做到了，`CitedReading` 组件 + RAG 链路是真实能力）。

### P2 · 产品级增量（需要你拍板）

8. **仿 Co-Star 做"今日快照"**：首页直接给一张今日牌 + 一句话解读，让用户零输入就有内容，再引导进入完整仪式。这是最贴近"今天对我意味着什么"的形态，但它要求 `/daily` 的数据与主页打通，工作量不属于"首页改版"。
9. **入口卡改底部 tab**：把三张入口卡做成移动端底栏、桌面端顶栏 sticky，贴近 CHANI 与同类应用的结构。收益是入口常驻，代价是占用一屏固定高度。

## 六、不建议做的事

**不要照抄 Co-Star 的单色极简。** 它的视觉克制是品牌定位的一部分，而且它已经有大量用户数据来补偿体验的朴素度。我们的人物 + 水晶球 + 星云是**差异化资产**，当前形态在同类里并不弱——问题在于它占据了不该占据的位置，而不是它不该存在。

**不要引入开屏付费墙或强制登录。** 评测里"五种内容类型 + 三条横幅 + 开屏付费墙"被明确点名为这一品类的典型失败模式；我们的定位是免费工具，沉浸感与仪式完整度才是护城河。

**不要把占卜师选择做得更重。** 多占卜师是这个产品真实的差异点（`personas` API + `PersonaOrb`），但它是**仪式参数**，不是**准入条件**。把它做成默认一位 + 可展开，既保留了差异又不挡住转化。

**不要在这一轮动配乐系统。** 刚完成的音频重做（7 段配乐 + 事件音效 + 空气层 + 阶段联动）与首页改版是两件独立的事，混在一起会让任何一侧的回滚变难。

---

## 七、需要你拍板的两件事

**一，是否接受 P0 的"重排"路线？** 它会让首屏从"海报"变成"产品"。审美上首屏会变"素"——人物图下移、背景留白增多。如果你更看重第一眼的气质而不介意用户往下滚，那么 P0 应该退一步，只做 P1（补功能说明、零门槛入口、信任信号），其余不动。

**二，要不要做 P2 的"今日快照"？** 它是这套方案里唯一能真正对标 Co-Star 的动作，也最可能拉开体验差距，但需要 `/daily` 与主页打通，工作量在首页改版之外。

---

## 八、尚未验证的部分

- **移动端首屏未实测。** 本次只截了 1280×720 桌面视口。移动端有 `ViewportScale` 等比缩放逻辑，首屏比例与桌面不同，P0 的像素阈值需要在真机上复核。
- **竞品均为 Web/App 混合形态**，部分结论来自 App 评测与官方 App tour 文档，未逐一在浏览器中复现其移动端布局。
- **当前首页的用户行为数据缺失**（无埋点），因此"用户实际在哪一屏放弃"属于推断而非观测。P0 完成后建议补一个"开始占卜按钮曝光 / 点击"的埋点，才能验证重排是否真的拉高了转化。
- **工作区里有一批未提交的 nebula 相关改动**（`NebulaDrift`、`CelestialBackdrop`、`globals.css`、两张 webp 素材），首页改版应在那批改动合并之后进行，避免两次布局调整叠加。
